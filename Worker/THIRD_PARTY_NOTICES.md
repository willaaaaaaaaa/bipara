# Third-party notices

Worker dependencies and versions are pinned in [pyproject.toml](pyproject.toml) and [uv.lock](uv.lock). Runtime and development/build dependencies are distinguished when [the collector](../script/generate_notices.py) runs inside the frozen environment.

The collector copies complete distribution license/copyright/notice files and the CPython license into ignored build/third-party, with README.md and inventory.json. The qualified Python archive build has pinned upstream component notices under [runtime license provenance](../licenses/python-runtime/README.md); development Homebrew builds also collect notices from the actual external dylib packages. The release worker bundles this directory as ThirdPartyLicenses. Additional build-package notices are supplied conservatively rather than described as runtime requirements. Missing runtime license text fails packaging.

Formal builds use the unchanged archive in the runtime manifest, rather than a uv-relocated installation. Python package source URLs and hashes come from the frozen lockfile. Native binary inputs are mapped to installed wheel attribution or the qualified Python notices, with bundle-relative names and input hashes in the inventory; unqualified external native dependencies fail packaging. PyInstaller rewrites/signs some binaries, so these hashes identify inputs, not final installed signatures.

The 2026-11-08 distribution review of the frozen environment found permissive MIT/BSD, Apache, PSF/CNRI terms and MPL-covered components. Preserve all supplied copyright/license/NOTICE text. In particular, `certifi` and `orjson` retain their MPL terms: formal packages also include their unchanged, checksum-verified source distributions under `ThirdPartyLicenses/sources/`, alongside their source URLs and full licenses. The app's MIT license does not replace these terms. See [MPL section 3](https://www.mozilla.org/en-US/MPL/2.0/) and [Mozilla's distribution FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/). Dependency, lockfile, runtime or native-component updates require a new scoped review; this record does not cover arbitrary later versions.

PyInstaller has a distribution exception; it does not select the project's license. See its [official license](https://pyinstaller.org/en/stable/license.html). Required terms of the actual bundled Python/dependency/native components still apply. The generated inventory is a distribution aid, not a completed legal compatibility audit.
