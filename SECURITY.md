# Security reporting

Report suspected vulnerabilities through the repository's **Security → Report a
vulnerability** entry when private vulnerability reporting is enabled. If the
entry is unavailable, request a private reporting channel without including the
vulnerability details in a public issue. Do not attach credentials, private
documents, personal machine paths or unredacted diagnostic archives.

Include the affected version, a synthetic reproduction, expected behavior and
impact. Credential/endpoint isolation, document integrity, worker execution and
release-asset integrity are security-relevant areas. Keep development commands and
dependency notices reproducible without sharing account credentials.

The project is experimental. Only the latest published release is a maintenance
target; no response-time or backport commitment is implied. Repository
administrators must enable private reporting and configure release protections
before public distribution; this file does not configure them.
