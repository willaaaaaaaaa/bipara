# Native Application Design

This document defines the native implementation contract. Design requirements and measured runtime behavior are separate; see [validation status](../validation.md).

The [model configuration design](model-settings.md) defines runtime endpoint/effort bindings, preferences migration and a single localized Settings entry.

Read [architecture](../architecture.md) for decision ownership, [model workflow](model-workflow.md) for text processing, [worker protocol](worker-protocol.md) for IPC, and [development plan](../development-plan.md) for delivery order.

## Build and module boundaries

Target macOS 26 and 27 on Apple Silicon, plus macOS 26 on compatible Intel Macs, with a minimum deployment version of 26.0. The Debug and Release app take their deployment target from `BIPARA_RELEASE_MINIMUM_MACOS` in `Config/Version.xcconfig`. Use availability checks and compatible fallbacks for APIs newer than the minimum. Only the maintainer's local OS receives runtime acceptance; other target versions remain unverified. This support policy does not add an upper-version launch block or promise compatibility with future macOS releases. Use Swift 6 language mode and system frameworks on the Swift side. Ship separate arm64 and x86_64 installers; universal packaging and mobile execution remain separate scope. Intel runtime acceptance is not required and must not be implied by a successful build.

Create one checked-in Xcode project, `Bipara.xcodeproj`, with shared scheme `Bipara`; use a root Swift package for `BiparaCore` and its tests. No project generator, dependency injection framework, database, server, or graph scheduler is needed.

| Location / module | Owns | Must not own |
| --- | --- | --- |
| `Sources/BiparaApp` | SwiftUI scenes, AppKit text bridge, workspace/settings stores, Keychain, native file panels, gateway composition | Prompts, provider HTTP parameter mapping |
| `Sources/BiparaWorker` | Foundation-only `PythonModelGateway`, child-process transport and lifecycle | AppKit views, document workflow or LangChain objects |
| `Sources/BiparaCore` | Foundation value types, document revisions, text ranges, paragraph/unit planning, job reducer, correspondence validation, document JSON codec | AppKit views, Keychain, Python or LangChain types |
| `Worker/bipara_worker` | Async pipe worker, LangChain invocations, provider adapters, model output validation | Tabs, files, document editing, scheduling whole documents |
| `prompts` | Versioned, complete system prompts, output schemas, synthetic cases | Runtime secrets or user-editable prompts |
| `Tests` / `Worker/tests` | Swift, native UI, cross-language and Python tests | Paid calls in the default suite |
| `docs/validation.md` | Concise current evidence and acceptance limits | Raw logs, credentials, or a second production translation engine |

The Xcode app target compiles `Sources/BiparaApp/BiparaApp.swift` and product assets and links the local package products. SwiftPM builds the same app directory as `BiparaAppKit`, excluding the entry point and product assets, so application state and native TextKit tests exercise the shipped code. `BiparaAppKit` depends on `BiparaCore` and `BiparaWorker`; the process adapter stays behind the typed `ModelGateway` seam. The bundle identifier is `dev.bipara.Bipara`; it does not establish App Store registration. Keep signing-team values out of Git. The app icon asset catalog uses the [current master](icons/README.md); actual size/masking review remains separate.

### Small interfaces

`ModelGateway` is the only Swift-to-model seam. Its two async operations are `translateBatch(request, configuration)` and `alignSelection(request, configuration)`, returning typed results or typed errors. Cancellation of the calling Swift task sends protocol cancellation. `PythonModelGateway` is the real adapter; `FixtureModelGateway` is the deterministic test adapter. Neither exposes `Process`, JSON dictionaries, or LangChain objects to document logic.

`DocumentCodec` encodes/decodes the file format below; file dialogs and atomic writes stay in the app. A shared Core `StrictJSON` preflight preserves the existing duplicate-key contract before Foundation decoding: validate UTF-8/size, scan object/array/string structure with an iterative stack, and track decoded keys per object without building a value AST. Decode escaped key strings with Foundation, compare their decoded UTF-8 bytes, then let Codable validate JSON grammar/types and fields. Thus `"a"` and `"\u0061"` in one object are duplicates, while the same key in separate objects is valid. This is a small common preflight for IPC/files, not a new JSON framework. `CorrespondenceResolver` resolves a reading position or selection against current ranges. Use plain functions/value types where these do not need state. Do not introduce generic repositories, buses, plugins, or arbitrary workflow interfaces.

An app-owned `TranslationCoordinator` runs the Core job reducer and dispatches batches through `ModelGateway`. Python executes one model operation per request; it does not independently split whole documents or retry them. `WorkspaceStore` and `SettingsStore` are MainActor-owned observable presentation state. Process I/O, JSON processing, text planning, and file I/O run away from the main actor; UI updates return through one serial application path.

## State and identities

Use UUID strings for document, paragraph, unit, job, and request IDs. IDs never derive from tab position or title. Use nonnegative integer revisions/generations; never reuse a closed tab's session identity.

| Value | Required content |
| --- | --- |
| `Document` | Persistent document ID, title, exact source string, source revision, resolved language direction, ordered paragraphs/units, committed translations and attribution |
| `TabState` | Fresh session ID, document, input draft, view mode, layout, reading anchor per layout, pinned selection, job state, session-local elapsed time, automatic-title ownership, save URL, content/save generation |
| `Paragraph` | ID, source UTF-16 range, exact separator range, ordered unit IDs; whitespace-only paragraphs are preserved but not translated |
| `TranslationUnit` | ID, paragraph ID, full source range and inner text range, kind (`sentence` or `fragment`); derive boundary whitespace from source; immutable within a source revision |
| `UnitTranslation` | Unit ID, translated text, returned model, completion time; requested provider/model/prompt attribution comes from its job snapshot |
| `JobSnapshot` | Job ID, source revision, resolved direction, provider ID, model ID, requested effort, adapter profile and prompt versions; portable attribution excludes private runtime binding. Runtime binding freezes configuration ID and Base URL; completed membership is derived from committed translations |
| `ReadingAnchor` | Paragraph ID, source/translation side, fraction through the paragraph's displayed height; clamp to a visible valid paragraph on restore |
| `Correspondence` | Source and target ranges, source revision, target generation, granularity, provenance (`unit` or `model`), and optional pinned state |

All native text ranges are UTF-16, half-open `[location, location + length)`. Resolve and validate against the exact current string. Check integer bounds, overflow, and composed-character boundaries. Python never manufactures native offsets. Preserve source code points, whitespace, and CRLF; do not normalize Unicode or rebuild the original from model output. For source/draft change detection, reconstruction assertions, selection partitions, unchanged-literal joins, and quote matching, compare UTF-8/UTF-16 code units exactly (for example, `utf8.elementsEqual`) and search with literal options. Swift `String ==` and default Foundation search use canonical equivalence and must not decide text identity here.

Each async result is admitted only when tab session ID, document ID, source revision and job snapshot still match its owner. Translation results additionally require the current translation attempt generation; alignment uses its independent selection generation and immutable unit target identity. Translation Cancel/Resume/Retry does not advance selection generation. A new/cleared selection, source edit, retranslation or tab close invalidates the relevant selection owner. A selection result must also match the selected unit ID, unit-relative reading-text range, and target generation. Keep that logical identity in the request, pin, and cache; RenderedTextIndex derives absolute display ranges after layout or insertion of earlier resumed paragraphs. Target generation belongs to that unit’s immutable committed translation, separately from document content generation. Completing an unrelated batch does not change it, clear its pin/cache, or invalidate its pending alignment. Source edits or retranslation invalidate the affected target generations. A matching title or document ID alone is insufficient. Increment the translation attempt generation on translation cancel/resume; invalidate the tab session before closing it.

## Job lifecycle and concurrency

States: `idle`, `queued`, `running`, `paused`, `failed`, `completed`. `paused` and `failed` retain all validated completed units. Empty input cannot enter `queued`.

| Event | Transition / effect |
| --- | --- |
| Translate | Resolve direction and provider configuration; snapshot them; queue unfinished units; increment attempt generation |
| Batch succeeds | Commit all validated units atomically; increment content generation; display each newly completed paragraph |
| Eligible unit mismatch | Replace the failed active batch with two smaller queued batches under the [translation retry policy](model-workflow.md#failure-and-retry-policy) |
| Eligible GLM rate limit | Keep the affected batch in the current attempt while [shared admission](model-workflow.md#glm-rate-limit-recovery) defers its one replay outside the physical worker pool |
| Cancel | Invalidate the attempt immediately, remove its queued work, cancel its active operation; enter `paused` |
| Resume / Retry | Reuse snapshot and completed units, increment attempt generation, queue only unfinished units |
| Batch fails | Preserve completed units; stop dispatching that document; enter `failed` with a recoverable explanation |
| All units committed | Enter `completed`; whitespace-only units count as already handled |
| Apply source or direction edit | Cancel old work, increment source revision, regenerate all paragraph/unit IDs, clear translations and mappings, enter `idle` |
| Retranslate | Explicit confirmation if results exist; create a new job using current model defaults and clear old translations/mappings |

Editing uses an input draft. Opening the editor does not mutate source or invalidate results. Apply is disabled during IME marked-text composition; applying different text/direction replaces the whole source revision. Cancel editing restores the prior document. First release does not implement incremental diff translation or editable translations.

Allow **four concurrent model operations globally**, counting translation and alignment together, and **up to two translation batches per document session**. Queue document sessions round-robin; a completed batch releases its slot before the next one is admitted. Allow at most one pending alignment per tab; a new selection supersedes it. Alternate alignment and translation admission when both queues are nonempty, so selection cannot starve translation and a burst of translation cannot starve selection. The Python worker rejects excess admission instead of adding another hidden queue. An eligible split takes the front of that document's queue and uses the same admission limits. A terminal batch failure stops further dispatch for that document; in-flight siblings drain and may still commit their completed work before the job enters `failed`.

Switching tabs changes no job ownership or scheduling. Completed results in background tabs mark those documents dirty. Translation progress is committed units / total nonblank units, not guessed tokens or wall-clock percentage. No token streaming in v1; show validated paragraphs and unit progress for oversized paragraphs.

The committed active model and translation direction apply to new jobs and confirmed Retranslate. Resume and phrase analysis use the original provider/model/profile/effort/prompt snapshot and private frozen endpoint binding. Resolve credentials per configuration before each dispatch, checking that the entry still exists with the snapshot vendor and endpoint; key rotation at that URL applies to future requests. A dispatched request retains its key. Deletion and vendor or endpoint changes block subsequent calls without switching configurations. Opened files require an explicit session-local binding before model calls; see [model configuration](model-settings.md#runtime-snapshots-credentials-and-portable-documents). Do not mix job snapshots within a document revision.

## Native reading surface

Use one primary SwiftUI `Window`, one dedicated settings window (`Window(id: "settings")`; accepted 2026-11-02 in place of the automatic `Settings` scene, which on the measured OS duplicates the app-menu command and ignores the app's explicit interface language — see [model configuration](model-settings.md)), native toolbar/menu commands, and an accessible tab strip. Multiple reading windows, a library sidebar, and a document database are outside v1. Minimum window size is initially 800 × 560 points; validate at 900 × 650 and larger with maximum reading size. These are design constraints to test, not prior measurements.

The AppKit bridge is a small `NSViewRepresentable` containing two `NSScrollView`/`NSTextView` pairs for Side by side or one pair for Paragraphs. Its purpose is native selection, text hit testing, range highlights, and scroll anchors. Use TextKit 2 layout; keep view ownership inside the representable/coordinator, and expose values/callbacks only. Do not create a native view for every paragraph. Text remains selectable and read-only in reading mode; a separate native editor handles source input.

Build a `RenderedTextIndex` from document ranges to displayed ranges. Pane-level idle guidance, pending layout lines, paragraph padding, and translation separators have no source span and must never be sent as selected user text. No untranslated message or per-pair label is inserted into reading text. Use paragraph layout spacing to align corresponding starts in Side by side: measure both intrinsic paragraph heights without alignment padding, then add their difference to the shorter side's trailing spacing. Never feed already padded heights into that calculation. Coalesce width/font/changed-paragraph invalidation; hover does not trigger measurement. Update changed paragraphs without rebuilding every text view or replacing the system selection on each progress event.

Reading layout tokens: 32-point reading inset per pane (24 below 1100-point window width), with Standard caps 720/800 points and default Wide caps 960/1080 points for Side by side/Paragraphs. Window uses available pane width minus insets. Paragraphs uses an 8-point source-to-translation gap and a 24-point gap before the next pair, one header key and a translation-side rule. Side by side retains 20-point paragraph spacing and paragraph start alignment. Headings follow the reading text edge. Use native toolbar/control sizing and 12-point secondary chrome. At narrow widths keep the selected Mac layout and wrap text; do not automatically switch layouts. These values are design starting points for native visual acceptance, not a claim that the browser's pixel layout maps exactly to AppKit.

Link scrolling using paragraph identity and intra-paragraph fraction, with a reentrancy guard. Save the active reading anchor before a tab/layout/font change; restore after layout. Complete pending scroll-view layout before sizing the document view; if legacy scrollers change the available pane width, perform one bounded reflow before restoring the anchor. Preserve the logical paragraph and usable text width with both legacy and overlay scrollers. Use paragraph anchors, not whole-document percentages. Hover does not scroll; expose a keyboard-accessible Reveal counterpart action when its match is offscreen.

Hover uses locally available mappings. Native text selection keeps the system selection appearance; use the selected adaptive preset background/underline for correspondence. A pin survives hover elsewhere until cleared/replaced. The bottom strip labels Phrase, Sentence, Fragment, or Paragraph match; model-derived phrase matches remain described as suggested correspondence. Keep selection-analysis progress separate from document translation progress. Cross-unit selection falls back immediately without a phrase request.

Commands: Command-T new tab; Command-W close active tab when the reading window is key (close Settings normally when it is key); Command-Return translate/resume; Command-1/2 layouts only in the reader; Command-comma Settings; Command-S save; Command-O open; Escape clears a pin or cancels the active sheet. Menu enablement follows focus and state; do not intercept ordinary editor navigation or IME input. Provide keyboard access to tabs, close buttons, layout, selection analysis, and reveal; VoiceOver announces tab title/status and match granularity without announcing every progress tick.

File contains New Translation, Open, Save, Export Translation and Export Bilingual. The reader's action menu contains Edit Original, Copy Original, Copy Translation and Retranslate. Copy Original uses the exact canonical source; Copy Translation uses assembled complete paragraphs and is disabled until the document completes, avoiding an unnoticed partial clipboard export. Ordinary native Copy still copies an explicit selection. Toolbar action labels follow state: Translate, Cancel, Resume, Retry, or Retranslate; Retranslate confirms before replacing results. Cmd-Return follows that same primary action except it never triggers Cancel. Input-mode Translate first commits the validated draft; it is disabled during marked-text composition. Empty tabs and failed preflight retain the draft.

## Settings and appearance

Settings has a draft and explicit Save/Cancel. Closing a changed Settings window offers Save, Discard, or Cancel. Save validates all fields first; do not apply half a preferences draft after a Keychain failure. A small persistence transaction writes prepared Keychain changes first and commits one encoded preferences record last; keep previous values for compensation if a later write fails. Serialize new credential reads with that transaction so they cannot observe a half-applied draft. If compensation fails, report the affected credential state honestly and leave Settings open. Never claim Keychain plus UserDefaults provides an ACID transaction.

| Setting | Default / allowed values | Effect |
| --- | --- | --- |
| Interface language | English / Simplified Chinese | All app chrome; source and translation stay unchanged |
| Appearance | System / Light / Dark; default System | All app windows, sheets, popovers and text surfaces |
| Translation Direction | Automatic (default), Chinese → English, English → Chinese | New jobs and confirmed Retranslate |
| Active Model | Existing stable configuration ID, or null when the list is empty | Shared with the toolbar. New jobs and confirmed Retranslate |
| Model configurations | List/editor and versioned fields in [model configuration](model-settings.md) | Independent model/effort/endpoint/alias; Add/Edit/Delete are draft changes |
| API key per configuration | Absent until entered; masked editor with Replace/Delete | Independent Keychain items; Cancel discards uncommitted edits |
| Reading Width | Standard / Wide / Window; default Wide | Both layouts, shared across tabs |
| Correspondence Color | Blue / Teal / Amber / Purple; default Amber | Adaptive local preview; native selection remains system-owned |
| Don't ask to save on close | Off by default | Opt-in discard at document save review only; running-stop and Settings review remain |
| Reading family | System / Serif; default System | System font or system serif with Chinese fallback |
| Reading size | 14–28 points; default 17 | Both languages and both layouts |
| Line height | Compact 1.45 / Comfortable 1.70 / Spacious 1.95; default Comfortable | Text layout only |

Use String Catalogs for English and Simplified Chinese, explicit app locale for localized SwiftUI and AppKit strings, and system accessibility sizing where applicable. Persist one versioned preferences record in UserDefaults, with schema/key migration defined in [model configuration](model-settings.md#preferences-and-keychain-migration). Reading layout is per-document and remains in the toolbar, not Settings.

Settings Save performs local field/credential persistence checks only, with no model request. Explain that model access is checked when a translation starts. The toolbar updates only the committed active ID using the existing serialized settings store. The [model configuration design](model-settings.md#settings-entry-and-model-management) specifies how to reconcile it with an open draft. Display job attribution separately. Verify exactly one localized Settings menu command/shortcut, including when Settings itself is focused.

Implement one `AppearanceController` on the main actor: set `NSApp.appearance` to `nil` for System, `NSAppearance(named: .aqua)` for Light, or `.darkAqua` for Dark. Do not also force conflicting appearances on individual windows/text views. SwiftUI and bridged AppKit content inherit the app appearance. In System mode, respond to the OS changing appearance while the app runs. Apple exposes this override through [`NSApplication.appearance`](https://developer.apple.com/documentation/appkit/nsapplication/appearance).

Use semantic system text backgrounds, separator, accent and native selection colors. Use the adopted source/translation foregrounds and four paired correspondence presets in [interaction](interaction.md#correspondence-colors). Resolve dynamic colors on the effective appearance; repaint even when highlight ranges are unchanged. The default named asset also follows Blue for compatibility. Increase Contrast strengthens the underline and gutter cue. Verify at least 4.5:1 reading-text contrast for both foregrounds on every fill. Retheme without replacing text storage, losing selection/pin, moving the viewport or invoking a model. Appearance changes take effect on Settings Save. Follow Reduce Motion; no skin engine or latest-OS glass dependency.

Elapsed time is session-local `TranslationElapsed` on `TabState`. `WorkspaceStore` observes job ID/state transitions under an injectable monotonic clock: queue/run starts an interval, terminal/pause stops it, same-job Resume/Retry accumulates, and a new job/source resets it. One small status subtree refreshes whole seconds; ticks cannot mutate jobs or remeasure the reader. An opened file starts with no historical duration, retaining a since-open explanation if resumed. Clock instants/durations are neither dirty content nor portable fields.

## Local files and close behavior

Use explicit Save/Open of a `.bipara` UTF-8 JSON file. Write schema version 2 and read supported legacy files as defined in the document format. No automatic session recovery or cloud sync in v1. New unsaved work is protected by close/quit prompts unless the user explicitly enables Don't ask to save on close. That preference discards unsaved document changes without writing a file; it is not autosave or recovery. Support paste and UTF-8 `.txt` import (optional BOM); unsupported encodings produce an error, never silent replacement. File import is local; it does not call a model. Export plain translated text or bilingual text only after the user selects a destination; identify partial translations before export. Missing paragraphs are marked as untranslated in bilingual export and block translation-only export until the user explicitly chooses partial export.

The [document format](document-format.md) owns exact fields, nullability, range encoding, attribution and a complete example. Persist unit boundaries so OS tokenizer updates cannot reinterpret saved translations. Validate complete source coverage, nonoverlap, ID references, direction and attribution before opening. Do not persist active request IDs, credentials, Keychain identifiers, endpoint URLs, selection caches, errors with raw provider bodies, or global preferences.

Unknown newer schema versions fail without rewriting the file. Text import reads at most the source limit plus BOM and an overflow byte before decoding. Limits: initially 1 MiB UTF-8 source and 20 MiB `.bipara` file, explicitly shown when exceeded; do not truncate. Check a planned document and each proposed batch commit against the encoded file-size limit off the main actor so completed work remains saveable; on overflow preserve the previous state and report a local document-size limit. Revisit limits only with measured evidence and a corresponding design update. Load into a fresh tab session, restore partial work as paused, and require an explicit Resume. Opening an already open file activates its tab. Opening a copied file with the same persistent ID uses independent runtime session/attempt ownership even when its saved job ID is identical.

Input-draft text/direction changes count as unsaved content before Translate or Apply. Save, including Save during close, first applies a changed editor draft locally under the same revision/planning rules as Apply, then saves that snapshot without a model call or credential. Empty/whitespace-only drafts may be saved; nonblank eligibility applies only to Translate. Disable Apply/Save during IME marked-text composition. If applying the draft clears existing translations, direct Save first offers Apply Changes and Save / Cancel with that consequence explained; the existing close sheet explains the same consequence when choosing Save. Planning or write failure keeps the tab and draft. A successful save clears draft dirty state only through the draft generation actually applied/saved.

Save a snapshot to a sibling temporary file, then atomically replace the selected destination; retain dirty state on failure. Serialize each entire Save operation (draft Apply/confirmation, snapshot and write) for its tab/destination: queue a new save behind the active one and capture its snapshot when it begins, so an older write cannot finish after and overwrite a newer one. Resolve destination identity from the parent directory and final filename (and existing file identity when present); reject a destination owned by another open tab, retaining the draft and asking for a different filename. Track content generation, not only source revision: a translation can arrive during save. Mark saved only through the generation actually written. Read-only UI state changes do not cause a close prompt, although layout/anchor are included in the next explicit save. Save URL and local bookmarks remain outside document JSON.

Closing a running tab first offers Keep Tab or Stop and Close. The latter stops that tab's job, then presents Save / Discard / Cancel for dirty content unless the saved skip-save preference is enabled; that option follows Discard directly. It never skips running-stop confirmation or Settings draft review. Cancel at the save stage keeps the tab and completed work in a paused state. A failed/cancelled save keeps the tab. After Save completes during close, recheck the current draft and content generation; newer unsaved work keeps the tab open. Closing the last tab leaves an empty workspace. Command-Q and closing the main window use the same sequential dirty-document review. Closing the main window leaves the app running; Window > Bipara or reopening from the Dock restores an empty reading window. Command-Q quits only after every tab resolves. No close action deletes an original input file. Worker termination occurs after the app's quit decision, not when Settings or the main window closes.

## Privacy and packaging

Store keys as configuration-scoped generic passwords in macOS Keychain, migrating legacy provider-scoped keys through the approved transaction. Display only presence and explicit replace/delete, never the stored key. Before sending text, disclose the selected destination host and that it receives source/context for translation and source plus existing translation for alignment. Record acknowledgement locally per provider/origin, as defined in [model configuration](model-settings.md); no consent on every hover. User text is data, never code, HTML, tools, or shell arguments.

Do not log prompts, keys, text, raw HTTP bodies, clipboard contents, or file paths. Diagnostic events may contain operation kind, sanitized error code, duration, byte counts and anonymous in-process request ID. Disable LangSmith/tracing and provider SDK debug logs. No analytics, accounts, background upload, or secrets in exported documents. Provider service retention policies are external; do not promise zero retention.

Bundle CPython and dependencies using the M0 PyInstaller `onedir` helper-app trial. Place `BiparaWorker.app` under the main app's `Contents/Helpers`, launch its executable directly with `Process`, set `LSUIElement` for the helper, and require stdout pipes to survive packaging. Let the helper bundle own its Frameworks/Resources layout; do not scatter Python libraries into arbitrary main-app resource folders. Package prompt/schema assets from their canonical repository files and verify hashes. No `pip`/`uv` download or dependency installation at end-user launch.

Use a direct-distribution development build initially; Mac App Store sandbox qualification is deferred. The helper and all nested binaries must be signed in the appropriate inside-out order before final signing/notarization. PyInstaller documents macOS architecture/signing constraints and distinct onefile/onedir behavior; these make an early packaged trial necessary. [PyInstaller macOS notes](https://pyinstaller.org/en/stable/feature-notes.html)

For a stable local Debug identity, install an Apple Development signing certificate in Xcode and set `CODE_SIGN_IDENTITY = Apple Development` and `DEVELOPMENT_TEAM = YOUR_TEAM_ID` in the git-ignored `Config/BiparaDebug.local.xcconfig`. Use the same team and bundle identifier for successive builds. The Bipara Debug target reads this configuration in both Xcode and `script/build_and_run.sh`. Without the local file, Debug uses ad-hoc signing. Release and UI-test targets have separate signing settings.

Measure bundle size, startup, RSS, process lifetime and copied-bundle operation. Preserve the local pipe-worker boundary when diagnosing failures. Public installers follow [releasing](../releasing.md): the initial policy is ad-hoc signing without Apple notarization, with explicit trust disclosure and installation qualification. The optional Developer ID policy retains notarization requirements.
